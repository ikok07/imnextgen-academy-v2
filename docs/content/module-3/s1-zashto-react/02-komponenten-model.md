React има една основна идея: интерфейсът се строи от **компоненти** — малки, самостоятелни парчета, които знаят как изглеждат и как се държат.

## Всеки интерфейс вече е дърво

Отвори който и да е сайт и мислено го нарежи. Ето например страница с продукти:

```steps
{"title":"Разглобяване на екран"}
---
**Страница** — най-външното парче. Съдържа всичко останало.
---
**Навигация** — лого, менюта, бутон за вход. Използва се на всяка страница, значи е отделно парче.
---
**Списък с продукти** — не знае нищо освен как да подреди карти една до друга.
---
**Карта на продукт** — снимка, име, цена, бутон. Едно и също нещо, повторено 20 пъти с различни данни.
---
**Бутон** — най-малкото парче. Появява се навсякъде, изглежда еднакво, държи се еднакво.
```

Точно това дърво описваш в React. Всяко парче е функция, която връща как изглежда.

## Компонентът е функция

```sandbox
{"title":"Четири компонента в едно дърво","height":420}
---
function Badge({children}) {
  return <span style={{background: "#eee", borderRadius: 12, padding: "2px 10px", fontSize: 12}}>{children}</span>;
}

function ProductCard({name, price, tag}) {
  return (
    <article style={{border: "1px solid #ddd", borderRadius: 8, padding: 16, width: 200}}>
      <h3 style={{margin: "0 0 8px"}}>{name}</h3>
      <Badge>{tag}</Badge>
      <p style={{fontWeight: 600, marginTop: 12}}>{price} лв.</p>
      <button>Купи</button>
    </article>
  );
}

function ProductList({products}) {
  return (
    <div style={{display: "flex", gap: 16, flexWrap: "wrap"}}>
      {products.map(product => (
        <ProductCard key={product.id} name={product.name} price={product.price} tag={product.tag} />
      ))}
    </div>
  );
}

export default function App() {
  const products = [
    {id: 1, name: "Лаптоп", price: 1200, tag: "техника"},
    {id: 2, name: "Мишка", price: 30, tag: "аксесоар"},
    {id: 3, name: "Стол", price: 210, tag: "мебели"}
  ];

  return (
    <main style={{fontFamily: "system-ui", padding: 16}}>
      <h2>Продукти</h2>
      <ProductList products={products} />
    </main>
  );
}
```

Промени един продукт в масива и виж как трите карти се обновяват. Едно описание — три различни карти.

```callout
{"type":"tip","title":"Опитай сам"}
---
Добави четвърти продукт в масива. После смени цвета на `Badge` — и забележи, че се сменя на трите места наведнъж. Това е разликата между компонент и копиран код.
```

## Правилата на компонента

```steps
---
**Името започва с главна буква.** `ProductCard`, не `productCard`. По това React различава твоя компонент от обикновен HTML етикет.
---
**Връща описание на екрана** (JSX) или `null`, ако не трябва да се покаже нищо.
---
**Получава данни само през props** — аргументите му. Не бърка в глобални променливи.
---
**Не променя това, което получава.** Props се четат, не се пипат.
---
**Е чист:** при едни и същи props връща един и същ резултат. Без изненади.
```

```callout
{"type":"danger","title":"Малка буква = мълчалив провал"}
---
Ако кръстиш компонента `productCard` и после го ползваш като `<productCard />`, React ще реши, че искаш HTML етикет с това име. Няма грешка в конзолата — просто нищо не се показва. Проверявай главната буква първо.
```

## Колко малки да са компонентите

Правилото е практическо: **компонентът прави едно нещо и се събира на един екран**. Ако скролваш, за да го прочетеш, вероятно вътре има поне два компонента.

Но не прекалявай в другата посока. Компонент, който се ползва само на едно място и съдържа два реда, обикновено е излишна церемония.

```takeaways
- Интерфейсът е дърво от компоненти; компонентът е функция, която връща описание на екрана.
- Данните влизат отгоре надолу през props.
- Име с главна буква, чиста функция, едно отговорност на компонент.
- Един компонент, много различни данни — оттам идва преизползваемостта.
