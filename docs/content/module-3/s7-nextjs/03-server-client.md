Това е най-важната идея в модерния Next.js — и единствената, която наистина обърква идващите от Vite.

**В App Router всеки компонент по подразбиране е сървърен.**

## Какво значи сървърен компонент

```steps
---
Изпълнява се **на сървъра**, при заявката или при сглобяването.
---
Кодът му **не се изпраща** на браузъра. Големите библиотеки вътре в него не тежат на потребителя.
---
Има достъп до базата, файловата система и тайните ключове.
---
**Няма** `useState`, `useEffect`, `onClick` — на сървъра няма кой да кликне.
---
Може да е `async` и да чака данни направо в тялото си.
```

```javascript
// app/courses/page.jsx - сървърен компонент
import {db} from "@/lib/db";

export default async function CoursesPage() {
  const courses = await db.course.findMany();   // право до базата

  return (
    <ul>
      {courses.map(course => <li key={course.id}>{course.title}</li>)}
    </ul>
  );
}
```

Няма `useEffect`, няма състояние за зареждане, няма API адрес по средата. Данните се вземат, преди HTML-ът да тръгне към браузъра.

## Клиентски компонент

Едно изречение най-горе на файла го превръща в клиентски:

```javascript
"use client";

import {useState} from "react";

export default function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

Това е React, който вече знаеш. Взема се, когато трябва интерактивност: състояние, ефекти, събития, браузърни API-та.

## Правилото за решение

```steps
---
Има ли `useState`, `useEffect`, `onClick`, `window` или `localStorage`? → **клиентски**.
---
Само показва данни? → **сървърен**.
---
Не си сигурен? → остави го сървърен и добави `"use client"`, когато нещо се счупи. Грешката е ясна.
```

```callout
{"type":"danger","title":"Директивата се разлива надолу"}
---
Сложиш ли го в компонент, **всичко, което той внася**, също става клиентско. Затова не го слагай в основния изглед — така цялото приложение се превръща в едностранично и Next губи смисъл.
```

## Правилната подредба

Вместо цялата страница да е клиентска, оставяш интерактивното парче най-долу в дървото:

```javascript
// app/products/page.jsx - сървърен
import {getProducts} from "@/lib/products";
import AddToCartButton from "./AddToCartButton";   // клиентски

export default async function ProductsPage() {
  const products = await getProducts();

  return (
    <div>
      {products.map(product => (
        <article key={product.id}>
          <h2>{product.name}</h2>
          <p>{product.price} лв.</p>
          <AddToCartButton productId={product.id} />
        </article>
      ))}
    </div>
  );
}
```

Само бутонът пътува до браузъра. Списъкът, форматирането и данните остават на сървъра.

```callout
{"type":"tip","title":"Сървърен компонент като дете на клиентски"}
---
Сървърен компонент не може да се **внесе** в клиентски. Но може да му се **подаде** през `children`:

`<ClientWrapper><ServerContent /></ClientWrapper>`

Така интерактивната обвивка остава малка, а съдържанието вътре — сървърно.
```

## Какво може да пътува през границата

Props от сървърен към клиентски компонент се сериализират. Може да подаваш числа, текст, масиви, обикновени обекти, дати. **Не може** да подаваш функции и класове.

```callout
{"type":"warn","title":"Типичната грешка"}
---
`<ClientButton onClick={handleClick} />` от сървърен компонент гърми: функцията няма как да бъде изпратена. Или обработчикът се дефинира вътре в клиентския компонент, или се ползва Server Action — темата след няколко урока.
```

```takeaways
- В App Router компонентите са сървърни по подразбиране.
- Сървърните имат достъп до данни и не тежат на браузъра, но нямат състояние и събития.
- `"use client"` се слага възможно най-ниско в дървото.
- През границата пътуват данни, не функции.
