В едностраничното приложение зареждането беше ритуал: състояние, ефект, индикатор, грешка, отмяна. В сървърен компонент е един ред.

```javascript
export default async function Page() {
  const response = await fetch("https://api.example.com/courses");
  const courses = await response.json();

  return <CourseList courses={courses} />;
}
```

Компонентът е `async` и чака. React рисува чак когато данните са тук.

## Кешът на Next

Next добавя кеширане върху `fetch` — и това е първото, което трябва да настроиш съзнателно.

```javascript
// без кеш - на всяка заявка наново
fetch(url, {cache: "no-store"});

// кеш с презареждане на всеки 60 секунди
fetch(url, {next: {revalidate: 60}});

// кеш до изрично обявяване за невалиден
fetch(url, {next: {tags: ["courses"]}});
```

```steps
{"title":"Как се избира"}
---
**Цени, наличности, лични данни** → `no-store`. Всеки потребител вижда актуалното.
---
**Блог, каталог, страници със съдържание** → `revalidate: 60` или повече. Сървърът рисува веднъж и раздава готовото.
---
**Данни, които се променят от твоя админ панел** → етикети. След промяна извикваш `revalidateTag("courses")` и кешът пада само за тях.
```

```callout
{"type":"warn","title":"Кешът хапе"}
---
Класическият случай: променяш нещо в базата, презареждаш страницата и промяната я няма. Не е бъг — това е кеш. Затова стойността се избира съзнателно за всяка заявка, а не се оставя по подразбиране.
```

## Данни право от базата

Ако базата е твоя, няма нужда от обиколка през HTTP:

```javascript
import {db} from "@/lib/db";

export default async function CoursesPage() {
  const courses = await db.course.findMany({
    where: {published: true},
    orderBy: {createdAt: "desc"}
  });

  return <CourseList courses={courses} />;
}
```

Никакво API по средата, никакво предаване на ключове към браузъра.

```callout
{"type":"danger","title":"Тайните остават на сървъра"}
---
Променлива от обкръжението без представка `NEXT_PUBLIC_` е достъпна само на сървъра. Сложиш ли `NEXT_PUBLIC_` пред ключ за база или платежен доставчик, той заминава в браузъра и всеки може да го прочете. Представката е за неща, които нямат нищо против да са публични.
```

## Няколко заявки едновременно

```javascript
// бавно - едно след друго
const user = await getUser(id);
const orders = await getOrders(id);

// бързо - заедно
const [user, orders] = await Promise.all([
  getUser(id),
  getOrders(id)
]);
```

Същият `Promise.all` от моста, на същото място в разсъжденията.

## Зареждане близо до мястото на употреба

В App Router не е нужно всички данни да се вземат в страницата и да се подават надолу. Всеки сървърен компонент може да вземе своите:

```javascript
// app/dashboard/page.jsx
export default function Dashboard() {
  return (
    <div>
      <Stats />       {/* взима си своите данни */}
      <RecentOrders />{/* и този */}
    </div>
  );
}

async function Stats() {
  const stats = await getStats();
  return <div>Приходи: {stats.revenue} лв.</div>;
}
```

Next разпознава еднаквите заявки в рамките на едно рисуване и ги изпълнява веднъж. Така пробиването на props през нивата отпада и тук.

```takeaways
- Сървърният компонент е `async` и чака данните направо в тялото си.
- Кешът на `fetch` се избира съзнателно: `no-store`, `revalidate` или етикети.
- Тайните ключове остават на сървъра; `NEXT_PUBLIC_` е за публични стойности.
- Независимите заявки вървят заедно с `Promise.all`; всеки компонент може да си вземе своите данни.
