Три вградени неща, които вършат повече за скоростта на сайта от всякаква ръчна оптимизация.

## next/image

```javascript
import Image from "next/image";

<Image
  src="/courses/react.jpg"
  alt="Курс по React"
  width={800}
  height={450}
  priority
/>
```

```steps
{"title":"Какво прави вместо теб"}
---
Преобразува в модерен формат (WebP, AVIF), когато браузърът го поддържа.
---
Прави няколко размера и сервира подходящия за екрана.
---
Зарежда изображенията извън екрана едва когато потребителят стигне до тях.
---
Пази мястото предварително, така че страницата да не подскача при зареждане.
```

`priority` се слага само на голямото изображение най-горе — то трябва да тръгне веднага. Сложиш ли го навсякъде, губиш смисъла.

```javascript
// изображение с неизвестни размери, което пълни контейнера
<div className="relative h-64 w-full">
  <Image src={course.image} alt={course.title} fill className="object-cover" />
</div>
```

```callout
{"type":"warn","title":"Външни адреси искат разрешение"}
---
Изображение от чужд домейн изисква изричен запис в `next.config.js` под `images.remotePatterns`. Иначе Next отказва да го обработи — умишлено, за да не се превърне сайтът ти в безплатен преобразувател на чужди снимки.
```

## next/font

```javascript
import {Inter} from "next/font/google";

const inter = Inter({subsets: ["latin", "cyrillic"], display: "swap"});

export default function RootLayout({children}) {
  return (
    <html lang="bg" className={inter.className}>
      <body>{children}</body>
    </html>
  );
}
```

Шрифтът се сваля при сглобяването и се сервира от твоя домейн. Няма заявка към Google, няма проблем с GDPR и няма момента, в който текстът подскача при смяна на шрифта.

```callout
{"type":"danger","title":"Кирилицата иска subset"}
---
Без `"cyrillic"` в `subsets` българският текст пада на резервен системен шрифт и сайтът изглежда различно от замисленото. Класическа грешка, която се забелязва късно.
```

## Кога се рисува страницата

```steps
---
**Статично** (по подразбиране) — веднъж при сглобяване. Най-бързо.
---
**С презареждане** — статично, но обновявано на интервал: `export const revalidate = 3600`.
---
**Динамично** — при всяка заявка. Включва се само когато четеш бисквитки, заглавия или `no-store` данни.
```

```javascript
export const dynamic = "force-dynamic";   // винаги динамично
export const revalidate = 60;             // статично с обновяване на минута
```

```callout
{"type":"tip","title":"Проверявай какво се е получило"}
---
`npm run build` изписва до всяка страница дали е статична или динамична. Ако страница, която очакваш да е статична, се оказва динамична, значи някъде четеш нещо зависещо от заявката.
```

## Малкото, което остава за теб

```steps
---
**Динамично внасяне** за тежки части: `const Chart = dynamic(() => import("./Chart"), {ssr: false})`. Библиотеката за графики не бива да тежи на страници без графики.
---
**`useMemo` и `useCallback`** — само когато измериш реален проблем. Преждевременната оптимизация добавя код и не решава нищо.
---
**Lighthouse** в инструментите за разработка на браузъра — показва конкретни числа вместо усещания.
```

```callout
{"type":"info","title":"Редът на важност"}
---
Изображения, шрифтове и прекалено много JavaScript са причина за бавен сайт в 90% от случаите. `useMemo` не е. Започвай от първите три.
```

```takeaways
- `next/image` поема формати, размери, отложено зареждане и запазване на мястото.
- `next/font` сервира шрифта от твоя домейн; за български — `subsets: ["cyrillic"]`.
- Страниците са статични по подразбиране; динамични стават, когато четеш нещо от заявката.
- Скоростта се губи в изображения, шрифтове и излишен JavaScript — не в липсващ `useMemo`.
