Най-честата причина едно React приложение да се зарежда бавно не са излишните рисувания. Причината е, че браузърът сваля целия код на приложението, за да покаже една страница.

## Проблемът

Приложението ти има редактор на текст, библиотека за графики и страница с настройки. Потребителят отваря началния екран — и сваля всичко трите, защото са в един пакет.

## Решението

`lazy` казва на инструмента за сглобяване: отдели този компонент в отделен файл и го свали чак когато потрябва.

```javascript
import {lazy, Suspense} from "react";

const Chart = lazy(() => import("./Chart"));

function Dashboard({showChart}) {
  return (
    <div>
      <h1>Табло</h1>
      {showChart && (
        <Suspense fallback={<p>Зарежда се графиката...</p>}>
          <Chart />
        </Suspense>
      )}
    </div>
  );
}
```

```steps
---
`lazy(() => import("./Chart"))` връща компонент, който се зарежда при първото показване.
---
`Suspense` показва `fallback`, докато файлът пътува по мрежата.
---
След първото зареждане файлът е в кеша и следващите показвания са мигновени.
```

## Кое си заслужава да се отдели

```steps
---
**Страници.** При React Router всяка страница е естествена граница.
---
**Модали и панели**, които се отварят рядко.
---
**Тежки библиотеки** — редактори на текст, графики, карти, четци на PDF. Една такава често тежи повече от цялото останало приложение.
---
**Административната част**, която обикновеният потребител никога не вижда.
```

```javascript
const Dashboard = lazy(() => import("./pages/Dashboard"));
const Settings = lazy(() => import("./pages/Settings"));

<Suspense fallback={<PageSkeleton />}>
  <Routes>
    <Route path="/dashboard" element={<Dashboard />} />
    <Route path="/settings" element={<Settings />} />
  </Routes>
</Suspense>
```

```callout
{"type":"warn","title":"Не режи на твърде малки парчета"}
---
Всеки отделен файл е отделна заявка. Разделянето на трийсет мънички парчета прави приложението по-бавно, не по-бързо. Режи по страници и по тежки библиотеки — не по компоненти.
```

## Къде да стои Suspense

Границата определя какво ще мига. Ако сложиш един `Suspense` около цялото приложение, при всяко зареждане изчезва целият екран. По-добре е да е около частта, която се сменя.

```callout
{"type":"tip","title":"Skeleton вместо въртележка"}
---
За `fallback` сложи сив скелет с формата на бъдещото съдържание. Така страницата не подскача, когато истинското съдържание пристигне — и се усеща по-бърза, макар да е същата.
```

## В Next.js

Там `loading.jsx` е точно този `Suspense`, само че готов. А за тежка библиотека в клиентски компонент:

```javascript
import dynamic from "next/dynamic";

const Chart = dynamic(() => import("@/components/Chart"), {
  ssr: false,
  loading: () => <ChartSkeleton />
});
```

`ssr: false` е за библиотеки, които пипат `window` и не могат да се изпълнят на сървъра.

```takeaways
- `lazy` + `Suspense` свалят кода чак когато потрябва.
- Режи по страници и тежки библиотеки, не по отделни компоненти.
- Границата на `Suspense` определя коя част от екрана мига.
- В Next.js `loading.jsx` и `next/dynamic` вършат същото.
