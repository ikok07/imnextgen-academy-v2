Досега писа код, който работи. Тази секция е за кода, който работи **добре**: бърз, достъпен и покрит с тестове. Започваме от производителността — но не както обикновено се преподава.

## Първо: кога изобщо не ти пука

```callout

---
Приложение с двеста реда и трийсет елемента на екрана няма проблем с производителността. Добавянето на `useMemo` навсякъде „за всеки случай“ добавя код, добавя зависимости за поддържане и не ускорява нищо. Първо измерваш, после пипаш.
```

## Кога компонентът се рисува отново

Три причини, само три:

```steps
---
**Промени се негово състояние** — `setState` в самия компонент.
---
**Пречертал се е родителят му.** Това важи независимо дали props-ите на детето са се променили.
---
**Промени се контекст**, който компонентът чете.
```

Вторият е причината за 90% от излишните рисувания и изненадва всички: **промяната на props не е условието**. Пречертае ли се родителят, пречертават се и всичките му деца.

```sandbox
{"title":"Родителят дърпа всички след себе си","height":460,"showConsole":true}
---
import {useState} from "react";

function Child({label}) {
  console.log("рисува се:", label);
  return <p style={{margin: "4px 0"}}>{label}</p>;
}

export default function App() {
  const [count, setCount] = useState(0);

  return (
    <div style={{fontFamily: "system-ui", padding: 16}}>
      <p>Брояч: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>

      <Child label="Дете А" />
      <Child label="Дете Б" />
      <Child label="Дете В" />

      <p style={{fontSize: 13, color: "#666"}}>
        Натисни бутона и виж конзолата: и трите деца се рисуват, макар че нито едно не получава count.
      </p>
    </div>
  );
}
```

## Инструментът, който показва истината

React DevTools (разширение за браузъра) има раздел **Profiler**. Записваш няколко секунди работа и получаваш точна картина: кой компонент колко пъти се е нарисувал и защо.

```steps
{"title":"Как се ползва"}
---
Отваряш Profiler и включваш „Record why each component rendered“ в настройките.
---
Натискаш записа, правиш действието, което ти се струва бавно, спираш.
---
Гледаш най-широките ленти — те отнемат най-много време.
---
Щракваш върху компонент и виждаш причината: „Props changed“, „Hooks changed“, „Parent rendered“.
```

Без този раздел гадаеш. С него виждаш, че „бавното" е един компонент, който прави тежко смятане при всяко рисуване — а не тридесетте, които си решил да обвиеш в `memo`.

## Най-евтината оптимизация: подреждане

Преди да посегнеш към `memo`, виж дали състоянието не стои твърде високо в дървото.

```sandbox
{"title":"Същият екран, състоянието свалено надолу","height":560,"showConsole":true}
---
import {useState} from "react";

function ExpensiveList() {
  console.log("тежкият списък се рисува");
  const items = Array.from({length: 5}, (_, index) => "Ред " + (index + 1));
  return <ul>{items.map(item => <li key={item}>{item}</li>)}</ul>;
}

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <div style={{marginBottom: 10}}>
      <button onClick={() => setCount(count + 1)}>Брояч: {count}</button>
    </div>
  );
}

export default function App() {
  return (
    <div style={{fontFamily: "system-ui", padding: 16}}>
      <Counter />
      <ExpensiveList />
      <p style={{fontSize: 13, color: "#666"}}>
        Броячът държи състоянието си сам. Натискай го — тежкият списък мълчи в конзолата.
      </p>
    </div>
  );
}
```

Състоянието живее в най-малкия компонент, който има нужда от него. Тогава пречертаването засяга само него.

## Вторият безплатен ход: children

Ако състоянието наистина трябва да е горе, подай тежкото съдържание като `children`. React не го пресъздава при пречертаване на родителя, защото елементът е създаден другаде.

```sandbox
{"title":"children не се пречертава","height":520,"showConsole":true}
---
import {useState} from "react";

function Heavy() {
  console.log("тежкото съдържание се рисува");
  return <p style={{background: "#f3f4f6", padding: 10, borderRadius: 6}}>Тежко съдържание</p>;
}

function Wrapper({children}) {
  const [count, setCount] = useState(0);
  return (
    <div style={{border: "1px solid #ddd", borderRadius: 8, padding: 12}}>
      <button onClick={() => setCount(count + 1)}>Пречертай ме: {count}</button>
      {children}
    </div>
  );
}

export default function App() {
  return (
    <div style={{fontFamily: "system-ui", padding: 16}}>
      <Wrapper>
        <Heavy />
      </Wrapper>
      <p style={{fontSize: 13, color: "#666"}}>
        Натискай бутона: обвивката се пречертава, но „тежкото съдържание“ се появява в конзолата само веднъж.
      </p>
    </div>
  );
}
```

Този похват няма цена — не добавя нито един hook — и решава изненадващо много случаи.

```takeaways
- Рисуване предизвикват три неща: собствено състояние, пречертан родител, променен контекст.
- Промяната на props НЕ е условието — родителят дърпа децата си независимо от това.
- Profiler-ът в React DevTools показва кой и защо се рисува. Без него гадаеш.
- Първо сваляш състоянието надолу и ползваш `children`; чак после memo.
