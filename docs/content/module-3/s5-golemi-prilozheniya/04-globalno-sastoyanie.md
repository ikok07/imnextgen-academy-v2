Този урок ще ти спести месеци излишна работа. Няма да учим Redux в дълбочина — ще научим кога изобщо стои въпросът.

## Двата вида състояние

```steps
---
**Състояние на сървъра** — продукти, поръчки, потребители. Не е твое: то живее в база данни, ти държиш копие. Нуждае се от кеш, презареждане и синхронизация.
---
**Състояние на клиента** — отворено меню, текущ таб, тъмна тема, съдържание на форма. Твое е и живее само в браузъра.
```

Повечето приложения, които „имат нужда от Redux", всъщност имат нужда от добър кеш за сървърните данни. Това е работа на React Query, не на Redux.

```callout
{"type":"danger","title":"Най-скъпата грешка"}
---
Копирането на сървърни данни в глобален магазин ръчно: заявка, запис в магазина, после ръчно обновяване на 5 места при всяка промяна. Това е стотици редове, които React Query върши с два.
```

## Стълбата на решенията

```steps
{"title":"Изкачвай се само когато е нужно"}
---
**`useState` в компонента** — работи за огромната част от случаите.
---
**Вдигнато състояние** при общ родител — когато две-три деца имат нужда.
---
**`useReducer`** — когато правилата станат повече от няколко реда.
---
**Context** — когато стойността трябва да стигне дълбоко.
---
**React Query** — за всичко, което идва от сървър.
---
**Zustand / Redux Toolkit** — когато клиентското състояние е голямо, четено от много места и предизвиква реални проблеми с рисуването.
```

Повечето проекти спират на пето стъпало. Това не е признак за простота — а за правилни решения.

## Как изглежда Zustand

Ако някога стигнеш до шестото стъпало, най-вероятно ще е това:

```javascript
import {create} from "zustand";

const useCartStore = create(set => ({
  items: [],
  add: product => set(state => ({items: [...state.items, product]})),
  clear: () => set({items: []})
}));

// в компонент - без доставчик, без обвивки
function CartCount() {
  const count = useCartStore(state => state.items.length);
  return <span>{count}</span>;
}
```

Няма доставчик около приложението и компонентът се абонира само за парчето, което ползва — затова смяната на друго поле не го пречертава.

## Как изглежда Redux Toolkit

```javascript
const cartSlice = createSlice({
  name: "cart",
  initialState: {items: []},
  reducers: {
    added: (state, action) => { state.items.push(action.payload); },
    cleared: state => { state.items = []; }
  }
});
```

Изглежда, че променя състоянието на място — всъщност Redux Toolkit ползва библиотека, която превръща това в нов обект. Redux носи повече правила и повече код, но и инструменти, които на голям екип вършат работа: пълна история на действията, връщане назад, стриктна структура.

```takeaways
- Раздели сървърното от клиентското състояние — това е най-важното решение.
- Сървърните данни отиват в React Query, не в глобален магазин.
- Стълбата: useState → вдигане → useReducer → Context → React Query → Zustand/Redux.
- Повечето проекти никога не стигат до последното стъпало.
