`useEffect` е най-злоупотребяваният hook в React. Затова започваме с обратното на обичайното: **кога да НЕ го ползваш**.

## Кога не ти трябва

```steps
{"title":"Четири случая, в които useEffect е грешен отговор"}
---
**За изчислени стойности.** Сметни ги при рисуването. Нямаш нужда от ефект, за да поддържаш `total`.
---
**За реакция на събитие.** Кликът, изпращането на формата и въвеждането се обработват в самия обработчик, не в ефект след промяната.
---
**За преобразуване на props в състояние.** Ако стойността идва отгоре, ползвай я направо.
---
**За да „изчакаш“ състоянието.** Новата стойност ти е известна — изчисли я в променлива.
```

```callout
{"type":"danger","title":"Класическата грешка"}
---
Ефект, който при промяна на `items` записва сума в друго състояние. Това предизвиква второ рисуване за нищо и създава момент, в който екранът показва стара сума. Просто сметни сумата при рисуването.
```

## Кога ти трябва

Ефектът е за **синхронизиране със света извън React**: мрежа, таймери, браузърни API-та, абонаменти, ръчна работа с DOM.

```sandbox
{"title":"Заглавието на таба - външен свят","height":420}
---
import {useState, useEffect} from "react";

export default function App() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    document.title = `Брояч: ${count}`;
  }, [count]);

  return (
    <div style={{fontFamily: "system-ui", padding: 16}}>
      <p style={{fontSize: 26, margin: "0 0 10px"}}>{count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <p style={{fontSize: 13, color: "#666"}}>
        Заглавието на таба на прегледа се сменя. `document.title` е извън React, затова е ефект.
      </p>
    </div>
  );
}
```

## Анатомия

```javascript
useEffect(() => {
  // тялото: изпълнява се СЛЕД рисуването
  return () => {
    // чистене: изпълнява се преди следващото изпълнение и при премахване
  };
}, [зависимости]);
```

Вторият аргумент решава кога тялото се изпълнява отново:

| Вторият аргумент | Кога се изпълнява |
| --- | --- |
| `[]` | само веднъж, след първото рисуване |
| `[value]` | при първото рисуване и всеки път, когато `value` се промени |
| липсва | след **всяко** рисуване (почти винаги грешка) |

```sandbox
{"title":"Трите варианта в едно","height":520,"showConsole":true}
---
import {useState, useEffect} from "react";

export default function App() {
  const [count, setCount] = useState(0);
  const [other, setOther] = useState(0);

  useEffect(() => {
    console.log("веднъж: [] - само при монтиране");
  }, []);

  useEffect(() => {
    console.log("при промяна на count:", count);
  }, [count]);

  useEffect(() => {
    console.log("след всяко рисуване");
  });

  return (
    <div style={{fontFamily: "system-ui", padding: 16}}>
      <p>count: {count} · other: {other}</p>
      <button onClick={() => setCount(count + 1)}>count +1</button>
      <button onClick={() => setOther(other + 1)} style={{marginLeft: 6}}>other +1</button>
      <p style={{fontSize: 13, color: "#666"}}>Натискай двата бутона и следи конзолата.</p>
    </div>
  );
}
```

```callout

---
`StrictMode` при разработка нарочно изпълнява ефектите двукратно, за да провери дали чистиш след себе си. В продукция това не се случва. Ако кодът ти се чупи от двойното изпълнение, значи наистина има проблем с чистенето.
```

## Правилото за решение

```steps
---
Стойността **изчислима** ли е? → сметни я при рисуването.
---
Причината е **събитие**? → напиши го в обработчика на събитието.
---
Синхронизираш с нещо **извън React** (мрежа, таймер, DOM, абонамент)? → тогава `useEffect`.
```

```takeaways
- Първо се питай дали изобщо ти трябва ефект — обикновено не ти трябва.
- Изчислимото се смята при рисуването; реакцията на събитие е в обработчика.
- `useEffect` е за синхронизация с външния свят.
- Масивът със зависимости решава кога тялото се изпълнява отново.
